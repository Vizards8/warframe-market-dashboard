# 虚空账本 V2：玩家使用方案

方案日期：2026-10-21。依据：当前已发布网页、现有代码，以及本次对话中的使用需求。这是供评审的产品方案，尚未做玩家访谈，也没有将下文示例当作当前行情或交易建议。

## 1. 产品要帮助玩家完成什么

优先服务国际服 PC、愿意等价、持有多份奸商商品的玩家。一次打开应能完成一个具体任务：

1. 今天哪些持仓值得重新核价、尝试挂出几份？
2. 奸商这次来了，我现有的杜卡德应该如何分配？
3. 四人开遗物，奖励出来后怎样迅速对照价格？
4. 刚开的零洗紫卡，先查哪里，是否值得继续研究词条？

首页不要求玩家每天必须交易。没有明显变化时，应直接说明“暂时没有需要处理的变化”。

## 2. 当前页面的具体问题

| 当前行为 | 对玩家的影响 | 改进方向 |
| --- | --- | --- |
| 首页主要展示库存总量、历史估值和目标达标数量 | 看完仍要逐行找变化；库存和关注混在一起 | 把持仓变化与待处理事项放在前面，库存、关注分开 |
| 目标达标使用当前选定的 7/30/90 天成交均价 | 换统计窗口就可能改变达标结果；历史均价不等于当前可卖价 | 明确比较依据，区分历史均价、卖方挂价与买方报价 |
| 新商品从品类表关注后才方便录入库存；武器没有独立浏览入口 | 添加持仓路径分散，难以发现目录外商品不受支持 | 全局“添加库存”，搜索中英文和别名，显示精确变体 |
| 目录只有套装、历史奸商 MOD 和四种库存武器 | 无法完整管理 Prime 散件或其他武器 | 先补齐可交易奸商武器，再逐步支持 Prime 散件 |
| 奸商页开头按历史毛回款展示前三 | 用户看到的第一组商品未必本次有售，也未必适合囤 | 默认先展示经核对的本次货单；历史目录单独入口 |
| 常规返场记录和目录不会随定时行情更新 | 用户容易以为“自动更新”包含了货单和返场时间 | 把市场、货单、目录的更新状态分别展示 |
| 核桃助手已有四列、全屏和两种排序 | 功能齐全，但游戏中仍要辨认多达 24 个候选掉落；按价排序会改变位置 | 区分准备与战斗查阅，固定布局，保留名称与图片 |
| 零洗紫卡候选来自一次历史扫描 | 高价排行榜容易被误当作全市场扫描；新热门武器可能缺席 | 搜索优先，明确覆盖与样本，候选定期重新筛选 |
| 数量直接增减，没有买卖记录 | 不知道赚了多少、等了多久；误减也难恢复 | 加轻量交易记录与撤销，保留直接校正数量 |
| 所有栏目都带较多介绍和通用摘要 | 占用游戏旁边的屏幕空间 | 各栏目只保留与当前任务相关的信息 |

## 3. 一期：先让现有功能真正好用

### A. 首页：我的持仓与变化

默认保留耐心持有的使用方式，不用全市场涨幅榜替代个人持仓。

首页上部按明确条件列出少量事项：

- 价格达到我设定的观察线：同时显示比较依据和查询时间。
- 本次奸商货单包含我的持仓：提醒供应变化，不自动要求卖出。
- 价格或记录量相对前一等长窗口出现明显变化：展示原值、现值、样本量。
- 部分行情失效或缺价：直接说明哪些结论暂时无法判断。

没有可靠的前后快照时，不展示“比上次上涨”；不能用首次访问时的默认零值制造涨幅。

持仓表优先显示：商品与变体、数量、目标价、当前卖单参考、当前买单参考、30 天均价、查询时间。成本和长周期指标在详情展开。收藏与实际库存分开计数。

增加全局“添加库存”：中文、英文、别名均可搜索；添加前确认普通/Prime/棱晶/破坏者，以及 MOD 等级。目录未覆盖要明确提示，不能无结果时让人以为物品不存在。

验收：无需打开商品详情即可核对数量和目标；添加一个已收录商品最多三步；修改数量可以撤销。

### B. 价格：让玩家看懂该拿哪个数做判断

一个商品提供三个明确分开的参考：

| 玩家意图 | 参考依据 | 限制 |
| --- | --- | --- |
| 我愿意等，准备挂售 | 不同在线卖家的低位报价、自己的目标价、历史成交区间 | 卖单只是竞争者报价，不保证成交 |
| 我愿意接受当前求购价 | 买单价格、数量、状态与查询时间 | 六小时快照可能已经失效，必须回 WFM 确认 |
| 我想了解长期表现 | 7/30/90 天成交记录、成交量、已有区间位置 | 90 天区间位置不是未来卖点或全年历史高位 |

目标观察允许选择比较依据，默认保持用户上一次选择，不能随图表统计窗口切换而悄悄改变。

多份库存不能按最高买价乘全部数量显示“可立即回收”。公开快照若保留完整买单深度，可按数量逐档测算；若只有前十档，则只显示可覆盖部分及数据范围，不推算剩余部分。

一期只提供“达到观察线，去 WFM 核价”的操作入口。按钮不自动发挂单、不自动私信。耐心挂售价、预期售出天数不由不透明公式直接生成。

验收：所有达标状态能解释“哪个数与哪个目标比较”；缺价、陈旧或样本不足时，不显示确定的买卖结论。

### C. 奸商：本次买什么、我已经囤了多少

将“奸商 MOD”调整为“奸商补仓”，覆盖 MOD 和可交易武器。

首屏显示在售/离场、剩余时间、货单来源与核对时间。本次货单优先从适用国际服的公开世界状态数据获取；具体来源、延迟和可用性在实现前核验。数据失败时显示“货单待核对”，保留手动勾选入口，不沿用过期货单冒充当前在售。

每个在售商品显示：

- 杜卡德与现金兑换成本；其他获取途径。
- 返场前与返场后的报价/成交数据；尚无足够历史时标明不足。
- 30 天成交记录量、在线低位卖价、买卖价差。
- 我的现有数量与成本；这次打算补多少。
- 假设售价下，每百杜卡德回款及资源机会成本后的差额。

提供预算篮子：填写本次杜卡德、现金和想保留的资源，手动选择数量后汇总占用。先不自动生成“最优购买数量”，因为成交能力、持有周期和资金集中程度不能从均价确定。

资源成本分别处理：买核桃垃圾换杜卡德的白金成本、自己刷资源的时间成本、兑换现金，以及之后交易所需现金。不同计算视角切换展示，避免把同一份资源重复扣减。历史售价情景必须标清，不写成未来净利润。

对库存较多的同品类商品提示集中程度；长期不返场只是观察信息，不能直接成为买入理由。

验收：首屏建议只来自已核实本次在售商品；用户可以在一屏看出已有多少、本次计划买多少、共消耗多少资源。离场后保存计划和本次货单，不再标为在售。

### D. 开核桃：准备时查，奖励出来时直接看

准备模式：保留四遗物输入，增加最近使用组合、四人同核桃一键填充和精炼等级批量设置。以后支持保存多个组合；不要求开奖时输入四个奖励名称。

战斗模式：

- 隐藏库存摘要、长说明、成本输入和无关导航。
- 保持四列顺序，与队伍约定的玩家顺序一致，名称旁标数字。
- 默认按金/银/铜分组固定位置，保留按价格排序的准备视图。
- 每个奖励优先展示可辨认的中文名、部位、图片、白金价和杜卡德；蓝图、枪机、枪管不可省略。
- 用少量强调标出候选掉落中的高价项；注明这是可能掉落，不能写成“本局选它”。
- 四列重复奖励采用一致名称和颜色；近价时允许玩家优先看杜卡德。
- 缺价明确显示未知，不能按零白金排到最后并误导选择；旧价显示相对时间。
- 缩放与紧凑布局，分别验证 1920×1080 全屏和 1366×768 笔记本。手机采用可读布局，不将桌面四列机械压缩。

先不做依赖实时识别游戏画面的自动选号。用户可以手动选择奖励来记账，但这属于事后记录，不进入倒计时的必经流程。

验收目标：四个遗物事先填完后，在游戏奖励阶段无需输入、无需联网查询；用实际游戏截图做至少十轮人工对照，记录查找用时和误认情况，再决定是否达到“约两秒找到一项”的体验目标。

### E. 数据状态：让“刷新”符合玩家预期

常驻一行状态：当前快照发布时间、商品报价年龄、未更新项数量。市场报价、成交统计、目录和奸商货单分别标时间。

在线版按钮可命名“检查行情更新”，文案明确获取公开快照。定时抓取失败保留旧价格和旧时间，缺价不补零。构建时间不能代替数据查询时间。下一次运行只能说“预计”，不能给出必定执行的倒计时。

首页需要公开的刷新结果摘要，包括查询覆盖率、成功/失败数量；当前构建尚未导出刷新状态文件。一期可展示上一次完成结果和 Actions 链接。实时进度若无可靠公开状态来源，先不做虚假的百分比动画，也不在网页内放 GitHub 写入凭据。

验收：网络失败、部分失败、过期与从未查询四种状态可区分；关闭本机服务不影响在线页面使用。

## 4. 二期：从看价格到知道自己赚了多少

### 交易记录与实际收益

增加“买入/兑换”“卖出”“数量校正”三种动作。默认日期为今天，常用操作只填数量与价格；支持撤销。

记录每批商品的白金或资源成本、日期、卖出数量与售价。数据由浏览器保存，备份格式迁移时连同交易记录导出。

报表分开显示已实现白金差额、剩余库存成本、当前历史参考估值、持有天数。资源获取时间与交易等待时间单列，不能把无人购买的挂单时间当作已确认收益。

这能回答“上次奸商囤了这些，几个月下来实际上赚了多少”，也为下一次补货提供个人经验。

### Prime 散件与套装

先支持散件持仓、可凑套数量、缺失部件。比较整套出售与散卖的报价情景，附成交记录量和需完成的交易笔数，不只列高价套装。

允许用户为自用保留数量，避免“盈利优先”把尚未做过的战甲或武器材料全部列入出售。

### 零洗紫卡

页面默认搜索武器，而非只看固定前三十。对所有已知武器展示“已覆盖/未查询/无合格挂单/数据过期”，未知绝不等于低于 20p。

低位挂价按独立卖家去重，显示中位参考、最低卖家价、在线样本和时间；高于参考不代表好词条就不值钱。小样本、异常便宜和旧挂单要分开标记，不能随意过滤后伪造稳定底价。

全武器采集采用遵守接口限制的分批轮询，热门候选较频繁更新，完整池较低频更新；页面明确两种覆盖的不同时间。具体频率待运行成本验证，不承诺全武器每六小时刷新。

零洗底价只服务“这张卡要不要继续研究”，后续若做词条比较，应单独建模，不把异质紫卡混成一个成交均价。

### 长期历史

WFM 现有 90 天窗口不覆盖很多囤货周期。需要从启用日起逐日保存可公开的价格与成交汇总，形成未来 180/365 天观察；不能补造过去不存在的半年或一年曲线。

将常规奸商、TennoCon、Prime 重生活动等已核实事件标到图上，区分事件类型，帮助玩家观察返场前后变化。历史行情应有可持久保存的位置，不能只依靠可淘汰的 Actions Cache。

## 5. 三期：再扩展“刷什么赚钱”与跨设备体验

原始需求包含赚钱效率，可以增加路线比较，但以可兑现收益为核心：核桃、仲裁换卡、竞技场刷内融等分别填写自己的实际用时、资源获取、成本和已售出数量。区分理论资源/小时、按报价折算的白金/小时和实际卖出收入/小时。

玩家勾选已有战甲、武器和可用增益后再比较路线，不用一套极限配装的理论效率代表所有人。没有可靠输入的项目不参与收益排名。

跨设备同步放在一期体验稳定以后：可选账号与私有存储，清楚显示同步状态和冲突处理。GitHub Pages 继续负责前端；个人库存不能通过公开仓库提交实现同步。账号、存储服务和维护成本需要作为独立设计决策。

## 6. 交付顺序

| 批次 | 范围 | 可验收结果 |
| --- | --- | --- |
| 1 | 数据状态、目标语义、全局添加库存、持仓与关注分离 | 用户能录入并正确理解自己的库存和价格 |
| 2 | 奸商本次货单、武器目录、预算篮子 | 返场时能完成一次有依据的手动补仓计划 |
| 3 | 核桃准备/战斗模式、固定布局、快捷组合 | 开奖时无需输入，实测减少找价时间与误认 |
| 4 | 交易记录、散件凑套、紫卡覆盖改进、长期历史 | 能回看真实收益，并支持更完整的持仓 |
| 5 | 个性化赚钱效率、可选跨设备同步 | 有真实个人数据后再比较路线与扩展基础设施 |

前三批可继续采用 GitHub Pages + Actions + 浏览器保存。方案评审通过后，按批次逐个实现和验证，不把全部功能一次塞进首页。
