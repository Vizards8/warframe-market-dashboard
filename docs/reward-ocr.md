# 网页奖励 OCR（试用）

不安装客户端、扩展或本机服务。开核桃页面提供三种输入：共享画面、粘贴 / 导入截图、手动输入奖励。共享默认按次识别，可选择“奖励出现时识别（试用）”。

## 点击识别

1. 用桌面版 Chrome / Edge 打开虚空账本 → 开核桃助手。
2. 选择中文 + 英文或仅英文，奖励数默认为“自动检测”，也可手动指定 1–4。点击“共享游戏画面”，在浏览器的授权对话框选择游戏窗口或游戏所在屏幕，**不要选择虚空账本标签页**。每次新会话需要重新授权；网页无法绕过。
3. 游戏开始前可先点“提前准备 OCR”，无需共享画面或导入截图。默认从国内 npm 镜像下载固定版本组件和模型，失败会自动切换本站，也可手动选择“本站优先”。每个资源显示下载量，连续 15 秒无新数据会换源，不再无限等待。通过 SHA-256 校验后缓存到浏览器；下次优先使用缓存，仅英文下载量更小。仍需要首次联网，无法保证所有地区的网络都可用。
4. 默认“居中奖励卡”按画面中央的奖励卡定位，以 16:9 安全区域计算宽度，避免将全屏均分而读到空白或其他玩家名字。检查绿色区域，让每格覆盖一个奖励的**完整名称**。蓝色文字模式先比较居中的 1–4 格布局：名称应落在格内、边界不穿过文字、每格有足够的文字。只在唯一布局满足条件时采用。不能确定时提示校准或手选数量，不根据 OCR 匹配成功的个数删除格子。不同 UI 缩放或截取范围可能需要选择“手动校准”；区域可在识别轮次间调整，下一轮生效。
5. 默认点击“识别一次”才取一帧并运行 OCR。网页或悬浮窗获得焦点时，也可按 Ctrl + Enter；忽略按键重复与输入框，**不能响应游戏前台的全局快捷键**。按蓝字提取完整名称块，保留原始多行排版，使用 Tesseract PSM 6 识别，不再猜换行并横向拼图。未完整匹配时最多复核一次：二值化、PSM 11、按返回文字框坐标恢复阅读顺序。不会把近似结果自动改成已确认。
6. 如果结果不准，先打开“预览 / 校准识别区域”，让每个绿色框完整覆盖奖励名称并尽量排除头像、按钮和其他文字；英文名称可切换“仅英文”。网页放副屏即可查看。较新的 Chrome / Edge 支持 Document Picture-in-Picture 时，“悬浮价格窗”可尝试在游戏上方显示结果。浏览器在后台可能限速，无法保证即时识别；独占全屏可能无法捕获或覆盖，建议窗口 / 无边框模式。
7. 点击“停止共享 / 取消识别”、浏览器原生“停止共享”、关闭网页或切离开核桃功能会停止共享并清除帧和结果。不会后台继续采集。

纯网页无法响应游戏前台的全局快捷键或静默截屏；从共享画面识别依赖用户主动授权的屏幕共享。网页快捷键只对网页或悬浮窗焦点生效。

## 反作弊边界

当前实现只处理用户明确导入的图片，或浏览器屏幕共享授权返回的画面帧。代码使用标准浏览器的 `getDisplayMedia`、`createImageBitmap`、Canvas 和 Tesseract.js；**没有打开 Warframe 进程、读取 / 写入游戏内存、扫描游戏文件、注入 DLL、模拟按键 / 鼠标或与游戏进程通信的代码**。OCR 识别在网页 Worker 中执行。

这说明本工具的实现路径不涉及游戏内存读取，但不能替 Digital Extremes 对游戏规则作解释，也不能承诺任何第三方程序在所有环境下都绝无封禁风险。若你希望采取最保守的方式，可以只用 Windows 自带截图工具截取一次、手动切回网页导入图片并识别；无需启用屏幕共享。

## 手动截图

使用 Windows 截图工具截取奖励界面（全屏截图更容易沿用相同的区域设置），切回开核桃页面，在未聚焦输入框时按 Ctrl + V，或点“选择奖励截图”。确认区域后点击“识别一次”。只在本机解析图片，不发送到服务器。若网络不允许加载 OCR 组件，可手动输入每行一个完整奖励名称。

## 匹配与价格

- 候选仅为当前遗物掉落目录的 596 种奖励（594 种可交易商品和两种 Forma），不会把所有 WFM 商品都当成奖励。
- 使用中英文名、标点 / 空格归一化、精确部件名和名称换行组合匹配；相似度和首两个候选的差距用于筛选近似匹配。这里的“近似”不代表经过校准的识别置信概率。
- 同格出现多个精确奖励名会提示歧义，避免裁切跨格后直接选错。中文 OCR 错字、部位漏字时允许搜索并手动确认。
- 只有完整名称精确匹配或手动确认，且参考价在 6 小时内、最近查询未失败，才参加“已确认奖励中参考价最高”提示。未确认、缺价、旧值不参与；相同价格可同时标记。
- OCR、悬浮窗、下方掉落和核桃价格页共用 `DeskCore.rewardQuote`：优先最近 30 个日历天的成交量加权均价；没有有效均价时回退有效的在线最低卖价，并明确标注“无有效均价，挂价仅供参考”。两者均无有效值时，OCR 可保留带时间的旧参考价，但不参与推荐；下方掉落显示待查询。均价显示一位小数，排序保留原始精度。
- 标记仅比较当前已确认且有有效报价的奖励，并不保证缺价或未识别的奖励更便宜。
- 价格沿用网站的 WFM **公开行情快照**，不是实时接口查询或成交承诺；按实际价格来源显示统计或挂单更新时间，Forma 显示不可交易。

## 隐私与实现

- 使用 Tesseract.js 5.1.1（Apache-2.0）与 tesseract.js-core / Tesseract 中英模型。组件和模型随网站部署；下载可选择 npmmirror 国内镜像或本站，均使用相同的固定版本与 SHA-256 校验。镜像只收到公共依赖下载请求，不收到截图或识别文字。下载完成后识别在浏览器 Worker 内运行。许可与来源见 `static/ocr/NOTICE.md`。没有截图上传 API、个人账号接口或本机连接器。
- 图片、共享流及 OCR 结果仅保存在当前页面内存；不写入浏览器库存、备份或 GitHub。关闭 / 停止后清除共享画面与结果，关闭页面释放 OCR 引擎。截图文件只有用户主动选择时才读取。
- `static/reward-ocr-core.js`：卡位计算、奖励数判断、蓝字提取、完整文字块、坐标阅读顺序、触发状态、候选匹配、报价与推荐规则。
- `static/reward-ocr-assets.js`：依赖下载、换源、校验、缓存及 Worker 资源映射；不接收截图。浏览器不支持缓存或隐私模式禁止写入时，仍可使用本次下载，关闭页面后可能需要重下。
- `static/reward-ocr.js`：网页输入、共享流生命周期、OCR Worker、区域预览、取消与可选画中画。
- `static/extras.js`：开核桃模块挂载、更新价格、离开时停止采集。

## 分辨率与校准

显示器分辨率、共享帧分辨率和奖励卡大小是三件事。预览中显示的是实际导入／捕获的像素尺寸，网页缩放不会直接改变图片坐标。2K 显示器也可能共享出更小的帧，或者游戏使用了不同的 UI 缩放。

本次用同一张截图运行生产裁剪、预处理和同版 OCR 模型：原始 2560×1440 为 3 个完整匹配、1 个近似；等比缩到 1920×1080 为 2 个完整匹配；缩到 1280×720 为 1 个完整、1 个近似。另在 2560×1440 画布上把截图绕中心缩放为 80%／125%，默认卡位都无法可靠匹配；下移 40 像素同样会失败。这是图片变换模拟，不是 Windows 游戏实测，也不能把模拟百分比直接当作游戏 UI 或 Windows 显示缩放数值。

遇到全空或乱码，先查看“预览 / 校准识别区域”和各格“识别原文 / 实际裁剪”。绿色框应分别覆盖完整奖励名；黑白裁剪应能肉眼读清名称。可在“调整识别区域”中调卡位缩放和上下偏移，复杂布局仍可手动设置四边。校准模拟的 80% 场景恢复到 3 个完整匹配，下移场景恢复到 3 个完整、1 个近似；125% 场景校准后只有 2 个完整，仍有文字识别问题。未匹配到任何奖励时自动展开原画面预览，不再只显示一排空结果。

裁剪预览和 OCR 原文仅留在当前页面内存，停止共享或关闭页面即清除；不上传、不写入持久缓存。

本次也在本机用同一中文 2K 截图尝试了 Tesseract PSM 11 整片奖励区识别：卡帕与 Yareli 被合到同一行，换行字有漏识别。整片识别后按文字框坐标分组是可选路线，但还需要解决跨栏、换行和重复奖励，不能直接数 OCR 行数。本版采用“先按文字分布判断数量，再逐格识别”，减少一次额外 OCR 和跨栏错误。名称仍从全部奖励目录匹配。

自动检测当前适用于默认蓝色名称；使用“其他颜色”时需手动指定数量。界面缩放和上下位置仍沿用校准参数，自动数奖励不等于自动校准所有 UI 设置。检测时根据文字覆盖、每格文字量、文字重心和边界是否穿字判断布局，不采用游戏日志、配置、进程或内存。

验证范围：原始 2560×1440 四格截图自动判断为 4 格。另把原图中的奖励名称区域在本机重排为居中 1–4 格，并等比生成 1280、1920、2560、3840 宽的画布，16 组布局判断均符合预期。这些是图片模拟，不能代替真实 1–3 人奖励界面及 Windows 共享实测。回归测试另覆盖空图、偏位、空缺中间格、重复奖励保留、两次点击间从 2 格变为 3 格，以及手选回退。


## 共享画面与粘贴截图结果不同（2026-10-27）

本次查看了页面中的成功粘贴结果：实际图片为 2560×1440，第三格“卡帕压力枪 Prime 蓝图”被整理为 499×66 的单行识别图。用户提供的共享失败页面截图中，同一名称仍保留为两行，原文为 `TRENE Prime &`。两条路径最终使用同一个识别函数；差别发生在输入像素和预处理结果，不能仅凭显示器是 2K 就断言两个输入相同。

已复现的缺陷：名称行与下一行单个“图”字在纵向投影中没有空白行，旧的 `titleLines` 将其合为一个高文字带，随后交给单行 PSM 7。截出失败页面中的该识别图，用同版模型回放，也得到 `*RENR Prime &` 一类无关文字。该复现基于页面截图中的裁剪图，不是 Windows 屏幕共享的原始帧。

修正：

- 对很高的文字带，只有出现明显的墨迹低谷、且后段明显更窄时才拆分，处理两行相接的情形。原有空白行分隔仍保留。
- 每格首次未完整匹配时，蓝字模式最多再尝试一次“去除淡背景 / 紧凑拼行”：固定二值化、无额外行间空格，重新放大字高。完整匹配不重跑；不会再次截屏，也没有定时识别。灰度文字模式不自动切换为蓝字。
- 两次结果按名称匹配状态比较，不按价格或物品是否在已填遗物中挑选。两次命名冲突时要求确认；近似候选不会升级成完整匹配。“识别原文 / 实际裁剪”保留两次图和文字，仅在本次页面内存中。
- 共享请求改为优先 3840×2160、`resizeMode: none`，并给轨道设置 `contentHint: detail`；共享流目标 5 帧/秒，上限 10，不等于每秒运行 OCR。浏览器仍可能忽略偏好或返回较小画面，不能保证它提供原始分辨率。
- 共享按钮下方直接显示源类型与实际取帧尺寸，取帧后以本次位图尺寸为准。不会读取屏幕外的游戏信息。

验证：失败页面裁剪经本机重建为蓝字后，生产网页的标准处理仍读错部位字，额外复核找回正确的卡帕蓝图候选，但原文仍有一个错字，因此保留为“近似匹配”。同一页面导出的成功粘贴裁剪回放仍完整匹配，且只跑一次。另覆盖相接换行、两次结果冲突、每格最多一次复核、共享像素偏好和实际尺寸显示。Windows 整屏共享尚未直接实测；本次证据不能确认浏览器是否真的降低了用户的共享分辨率。


## 多行名称与可选自动触发（2026-10-27）

此节描述当前实现；上文的单行拼接与相接行拆分是历史排查记录，已替换。

名称不再按像素投影手写拆行，也不再把最多三条裁剪拼为单行。程序先过滤小墨点、找完整文字块，保留所有行的相对位置，适当放大后交给多行 OCR。识别返回的行／块按纵向位置和横向位置组合，名称匹配支持连续多行，不区分“一行／两行／三行”特例。默认纵向搜索范围从画面 37.5–44% 扩大到 36–49%，减少下方换行被截掉的情况；仍是受限的名称区域，并非自动定位任意 UI，超出范围或文字配色不符时需校准。

“奖励出现时识别”默认关闭，不持久保存启用状态，只有已共享且选择蓝色文字时可开启：

1. 每秒在 Canvas 中检查一次缩小的名称区域，尺寸最多 800×240；此步骤仅统计蓝字分布，不调用 OCR、不创建完整截图位图、不请求行情或上传画面。
2. 唯一 1–4 格布局稳定约两秒后，提取一张完整共享帧，按正常流程识别一批奖励。每格最多两次 OCR（首次＋一次复核）。
3. 无论识别成功、未匹配或出错，同一画面均不自动重试。即使名称随后轻微变化，也不会反复识别。手动“识别一次”仍可用。
4. 名称布局连续消失至少五秒后重新待命；下一轮稳定画面可以再次触发。短暂闪烁不会重新识别。慢速淡入对比本次稳定起点，避免只比相邻两帧就误判稳定。
5. 关闭开关会停止后续检查；已开始的本批识别允许完成。停止共享、浏览器原生停止、离开开核桃功能或关闭页面会取消检查与正在运行的识别，释放共享流和 Worker。更改识别区域、语言或配色也会关闭自动触发，需手动重新启用。
