# 首页与 WFM 联动

核验日期：2026-10-21，国际服 PC / 跨平台。

## 最初交付（连接器更新见文末）

- 首页：虚空主题动效、库存 / 奸商 / 遗物入口、三步引导。已有持仓默认回工作台；新用户可选以后直接进入工作台。左侧品牌和“启航首页”随时返回。
- 侧栏：导航优先占用剩余高度，768px 笔记本可显示完整导航；极矮窗口允许细滚动条，手机维持横向导航。动效遵循减少动态效果设置。
- WFM 只读核对：顶栏打开，填写公开用户名。在线版打开官方 JSON 后复制粘贴；本地服务版可直接读取。无需密码和令牌。
- 商品按官方 itemId 匹配。只处理目录内可见卖单，MOD 必须明确 R0；买单、隐藏单、不明确等级、带子类型或充能等变体跳过。所有价格保留每笔交易份数，不将批量总价冒充单价。
- 差异预览默认不勾选。确认的商品数量设为所选挂售数量，不累加；缺失商品不清空。数量校正可整体撤销，不产生卖出收入。挂售数量可能小于实际持有，不能自动代表全库存。
- 公开站点没有账号令牌或私有写入接口；下方更新说明新增的本机挂单管理功能。

## 官方接口能做什么

| 需求 | 官方接口 | 边界 |
| --- | --- | --- |
| 读取公开挂单 | `GET /v2/orders/user/{slug}` | 匿名只返回可见挂单；slug 小写，与显示昵称可能不同 |
| 读取本人的全部挂单 | `GET /v2/orders/my` | 需要认证，可读取隐藏单 |
| 创建挂单 | `POST /v2/order` | 需要本人认证、账号已验证；必须匹配物品变体 |
| 改价 / 数量 / 显隐 | `PATCH /v2/order/{id}` | `platinum`、`quantity`、`visible`；需要本人认证 |
| 批量显隐 | `PATCH /v2/orders/group/{id}` | 可按买卖类型控制 all / ungrouped；需要认证 |
| 标记成交 | `POST /v2/order/{id}/close` | 会生成交易记录；不应拿来实现普通下架 |

WFM 不提供游戏仓库读取接口。WFM 上下架、删除挂单和实际游戏成交不能互相等同。

## 为什么 Pages 不能直接完成全部联动

1. 当前实测公开订单响应没有允许本站跨域读取的 `Access-Control-Allow-Origin`；浏览器直连受 CORS 限制。不能用 `no-cors` 读取响应，也不使用第三方公共代理传递数据。
2. GitHub Pages 提供静态文件，不能保管每个用户的写入授权，也不能在关页后持续执行。不能把令牌放公开仓库、静态 JS、分享 URL 或公共 Actions。
3. 官方文档说明公共 OAuth2 仍未开放，第三方暂不能注册自有 OAuth 客户端；需要认证的集成当前仍依赖旧认证流程。不能把“点击 WFM 授权登录”展示成已经可用。
4. 官方规则将自动化 / tradebots 描述为灰色地带，未来可能有更严格约束，不等于所有自动追价都获得许可。

## 初始设计（本机方案实现见文末更新）

采用 Pages 前端 + 用户自己的本地连接器，或带私有账号存储的独立后端。首先只读全部本人挂单；再做“拟变更 → 用户确认 → 限速提交 → 回读核验”，展示精确变体、旧价、新价和数量。显隐管理和成交记账分别设计。持续追价机器人不作为默认功能。

本地连接器中的授权应仅保存在本机安全存储，写入接口仅限允许的本机来源，不能成为接受任意 URL 的开放代理。当前新增本地接口只接受合法用户名，只访问固定官方公开 GET 地址，复用现有请求限速；使用可识别项目的 User-Agent，不发送凭据。

## 2026-10-21 更新：本机交易连接器已实现

无需等待 OAuth 即可通过现有会话令牌接入。新增独立本机服务端口 **18766**，与旧行情服务 18765 分开。双击 `启动WFM连接器.command`（或 `python3 server.py --wfm`），在本机页面粘贴当前 WFM Authorization 值（也接受单独的 `JWT=值`，转为旧版 `Authorization: JWT …`，不转发 Cookie，需 `/me` 实际验证）；官方 `/me` 返回本人账号后再读取 `/orders/my`，包含隐藏单。不会调用仅限第一方的新版登录接口，也不伪装官方客户端。

- 原在线网页的「WFM 挂单」打开本机连接页。授权后本人挂单会通过指定来源、指定窗口、随机通道回传，网页无需手动粘贴 JSON；令牌始终不跨窗口传递。
- 连接页支持逐条价格 / 数量修改、逐条和勾选批量显示 / 隐藏，保留买卖类型、等级、星数、子类型、充能、每笔份数。**本轮管理现有挂单，新建挂单仍在 WFM 官网操作。**
- 改动先由服务端读取本人挂单并生成 5 分钟有效的一次性预览。用户确认后执行前再次比对远端版本；官网已有变更则跳过，执行后回读核实。WFM 未提供原子条件更新，因此不能彻底消除“核对与写入之间”的并发窗口。
- 不调用删除或标记成交接口。写入超时不自动重试，尝试回读确认。批量结果逐项显示已确认 / 冲突 / 未确认 / 跳过，授权过期或限速会停止后续提交。
- 授权仅保留在本机内存，不写入 argv、环境变量、日志、文件、浏览器存储、个人备份或公开构建。断开清除本机令牌，不撤销 WFM 官网会话；令牌过期、服务重启后需要重新授权。
- 私有接口不开放跨域，只接受本机 Host / Origin；所有写操作需要 CSRF 请求头，页面禁止被 iframe 嵌入。不使用 `no-cors`、公网代理或公开 Actions 中的个人凭据。
- 当前只同步 WFM 上登记的挂单，不读取游戏仓库。回传的隐藏卖单可供手动数量核对，买单和不匹配变体仍不合并持仓。

验证新增私有会话、显隐、R0/R10 区分、过期授权、乐观并发冲突、一次性预览、写入超时回读、精确 PATCH 范围与令牌不进入命令行等测试。浏览器使用明确标识的模拟账户完成连接 → 回传原网页 → 改价 → 上架 → 下架 → 断开。**尚未使用真人会话调用受保护 API；真实账号联调需要用户在本机页面完成授权。**

官方依据：[现有 v1 授权仍用于集成](https://docs.warframe.market/docs/intro/)、[v1 令牌兼容与 scope all](https://docs.warframe.market/docs/api/overview/)、[新版登录接口仅限第一方](https://docs.warframe.market/docs/api/authentication/)。

Cookie 接入参考为[旧版社区示例](https://github.com/NKN1396/warframe.market-api-example)，不代表当前 Cookie 会话已完成真实联调。公开 `/user/{slug}` 响应成功不能证明具有本人读写权限。不要向聊天发送令牌、Cookie 或带凭据的 curl。

## 2026-10-21：免安装书签只读探针

新增 `wfm-bookmark.html` 设置页与自包含 `static/wfm-bookmark.js`。书签限制在 `https://warframe.market` 运行，创建浮动面板；用户点击读取后，以 `credentials: include` 向固定官方 API 发 GET `/me`，账号校验通过后间隔 650ms 发 GET `/orders/my`。不读取 Cookie / 浏览器存储，不提取 JWT，不跨窗口传输，不使用远程脚本或第三方代理。不提交任何写请求。

验证仅覆盖构建后的书签地址与源码一致，以及模拟响应的权限错误、跨域失败、隐藏买卖单、空列表等。实际尝试执行无账号访问的 DOM 探针时，自动化浏览器禁止 `javascript:` URL，并要求不得绕过；因此没有执行 WFM 内脚本，没有完成真人会话读取，更没有验证 Cookie 写入所需的 CSRF 或页面策略。此工具明确标为只读实验版，供使用者在常用浏览器直接测试。读失败不表示空库存，读成功也不表示可以写入。

## 2026-10-21：书签 v0.2 管理面板

使用者反馈只读探针的 `/me` 与 `/orders/my` 均为 HTTP 200，返回本人 28 条挂单，含隐藏买卖单。因此读会话已获得人工验证；不把这份私人挂单内容写入仓库。v0.2 新增官方 `/items` 中文目录（Language: zh-hans，credentials: omit；语言头跨域失败可回退英文）、搜索筛选、价格 / 数量编辑、逐条与勾选批量显隐。

变更预览重新读取 `/me` 与 `/orders/my`，验证账号、已验证状态、ownership、订单版本与精确变体，只允许 platinum / quantity / visible。一次性计划在闭包内保留 5 分钟，取消或重新同步清除。提交前重新验证账号和单条订单版本，再以 Cookie 会话 PATCH `/order/{id}` 精确字段，回读全部相关字段核实；批量逐条限速执行，错误停止后续。没有服务端条件写入，因此保留检查与写入之间的并发窗口；批量非原子，成功项不自动回滚。超时不重试写，回读确认一次。

不读取 Cookie / JWT / 浏览器存储，不伪造 CSRF 或 Authorization，不传送私人数据到行情站点，不调用删除 / 成交 / 新建接口。官方文档没有明确 Cookie 写入的 CSRF 约定，本轮没有实际验证；如被拒绝会显示 HTTP 403 并停止，不绕过。只有使用者自行选定、预览并确认后才会发 PATCH。自动化浏览器此前已拒绝 javascript: 执行，不再重试或绕过；当前通过模拟传输验证写入逻辑，并在独立本机模拟界面验证交互，不能当作真实 WFM 写入证据。

升级需重新保存自包含书签，并刷新 WFM 后点击新版，避免旧面板复用。书签设置页和正式首页入口明确标示 v0.2 写入待实测。
