# 首页与 WFM 联动

核验日期：2026-10-21，国际服 PC / 跨平台。

## 当前交付

- 首页：虚空主题动效、库存 / 奸商 / 遗物入口、三步引导。已有持仓默认回工作台；新用户可选以后直接进入工作台。左侧品牌和“启航首页”随时返回。
- 侧栏：导航优先占用剩余高度，768px 笔记本可显示完整导航；极矮窗口允许细滚动条，手机维持横向导航。动效遵循减少动态效果设置。
- WFM 只读核对：顶栏打开，填写公开用户名。在线版打开官方 JSON 后复制粘贴；本地服务版可直接读取。无需密码和令牌。
- 商品按官方 itemId 匹配。只处理目录内可见卖单，MOD 必须明确 R0；买单、隐藏单、不明确等级、带子类型或充能等变体跳过。所有价格保留每笔交易份数，不将批量总价冒充单价。
- 差异预览默认不勾选。确认的商品数量设为所选挂售数量，不累加；缺失商品不清空。数量校正可整体撤销，不产生卖出收入。挂售数量可能小于实际持有，不能自动代表全库存。
- 公开站点没有账号令牌、写入接口、后台同步任务，代码没有自动改价或上下架功能。

## 官方接口能做什么

| 需求 | 官方接口 | 边界 |
| --- | --- | --- |
| 读取公开挂单 | `GET /v2/orders/user/{slug}` | 匿名只返回可见挂单；slug 小写，与显示昵称可能不同 |
| 读取本人的全部挂单 | `GET /v2/orders/my` | 需要认证，可读取隐藏单 |
| 创建挂单 | `POST /v2/order` | 需要本人认证、账号已验证；必须匹配物品变体 |
| 改价 / 数量 / 显隐 | `PATCH /v2/order/{id}` | `platinum`、`quantity`、`visible`；需要本人认证 |
| 批量显隐 | `PATCH /v2/orders/group/{id}` | 可按买卖类型控制 all / ungrouped；需要认证 |
| 标记成交 | `POST /v2/order/{id}/close` | 会生成交易记录；不应拿来实现普通下架 |

WFM 不提供游戏仓库读取接口。WFM 上下架、删除挂单和实际游戏成交不能互相等同。

## 为什么 Pages 不能直接完成全部联动

1. 当前实测公开订单响应没有允许本站跨域读取的 `Access-Control-Allow-Origin`；浏览器直连受 CORS 限制。不能用 `no-cors` 读取响应，也不使用第三方公共代理传递数据。
2. GitHub Pages 提供静态文件，不能保管每个用户的写入授权，也不能在关页后持续执行。不能把令牌放公开仓库、静态 JS、分享 URL 或公共 Actions。
3. 官方文档说明公共 OAuth2 仍未开放，第三方暂不能注册自有 OAuth 客户端；需要认证的集成当前仍依赖旧认证流程。不能把“点击 WFM 授权登录”展示成已经可用。
4. 官方规则将自动化 / tradebots 描述为灰色地带，未来可能有更严格约束，不等于所有自动追价都获得许可。

## 推荐下一阶段

采用 Pages 前端 + 用户自己的本地连接器，或带私有账号存储的独立后端。首先只读全部本人挂单；再做“拟变更 → 用户确认 → 限速提交 → 回读核验”，展示精确变体、旧价、新价和数量。显隐管理和成交记账分别设计。持续追价机器人不作为默认功能。

本地连接器中的授权应仅保存在本机安全存储，写入接口仅限允许的本机来源，不能成为接受任意 URL 的开放代理。当前新增本地接口只接受合法用户名，只访问固定官方公开 GET 地址，复用现有请求限速；使用可识别项目的 User-Agent，不发送凭据。

## 验证

- Python 测试覆盖静态发布无私人库存、资源 hash 完整、自包含格式和原有行情处理。
- JS 测试覆盖 WFM 买单 / 隐藏 / 非 R0 / 未知变体排除、批量份数、重复单、错误响应和空列表。
- 浏览器测试在独立本机预览中核对：空列表不改库存、仅所选商品覆盖、其余数量保留、整体撤销；1366×768、1366×500、390×844 和桌面布局。
